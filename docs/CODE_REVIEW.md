# Critical code review

Reviewed the application, entry points, configuration, deployment files and tests against baseline commit `a427bcf`. The refactor addresses the findings below. Severity reflects concrete runtime consequences and extension cost; this is not a claim that the application has no remaining defects.

## Findings addressed

| Priority | Finding and failure scenario | Change and evidence |
| --- | --- | --- |
| High | `Processor.start` acquired the run lock and published state before entering startup error handling. A failed state-file write could leave ownership held without a worker. Publication failures during a job could also turn a healthy operation into a failure. | [Processor](../app/processor.py) isolates status publication and releases ownership on startup failure. Tests cover publication failure, thread creation failure, concurrent starts and shutdown. |
| High | `_job` wrote `failure.json` before the remote failure update without guarding that write. Disk exhaustion or permissions errors could strand a row at `PROCESSING` and abort the rest of the batch. Workspace creation also occurred outside the job's failure boundary. | [JobRunner](../app/execution.py) independently attempts diagnostics and failure updates, with workspace preparation inside the per-job boundary. Regression tests verify later jobs still run. |
| High, architectural | `Processor` directly constructed Baserow, download, transcription and upload adapters while owning threading, planning, rendering, files and recovery. A provider change required editing orchestration and tests patched its module globals. | [Contracts](../app/contracts.py), [composition](../app/bootstrap.py), [media pipeline](../app/pipeline.py), [runner](../app/execution.py) and [workspace](../app/artifacts.py) separate those concerns. Application tests inject providers directly. An architecture test prevents concrete provider imports in core modules. |
| Medium | There was no explicit guard against reacquiring an owned `RunLock`, and a successful reacquisition would replace its stored handle. Errors other than contention were treated as “busy”; release did not guarantee handle closure. Valid JSON of the wrong shape could break status consumers. | [RunLock](../app/state.py) rejects acquisition while owned, distinguishes expected contention errors, closes handles in `finally`, and validates shared-state shape. Tests cover repeated acquisition, cross-process exclusion and malformed JSON. Windows behavior was reviewed but not executed locally. |
| Medium | Several adapters imported cancellation from the renderer, bringing unrelated rendering, font and image dependencies into network code. Transcription also imported its subprocess runner from the renderer. | Shared cancellation and subprocess code now live in [cancellation.py](../app/cancellation.py) and [ffmpeg.py](../app/ffmpeg.py). Existing imports of `Cancelled` and `run_ffmpeg` from `video_builder` remain compatible. |
| Medium | Falsey YAML roots (`false`, `0`, `[]`, empty string) were silently replaced with defaults. List/dict enum values could raise an incidental `TypeError`; boolean numbers passed some numeric validation. | [Configuration](../app/config.py) distinguishes empty YAML from invalid roots and rejects invalid enum shapes and boolean numbers. Regression tests exercise those inputs. Provider credential checks are separately composable. |
| Medium | Transcription parsing assumed a dictionary, dictionary words and well-shaped segments. Invalid responses could raise `AttributeError`/`KeyError`/`TypeError`; booleans were accepted as timestamps. Audio probing accepted NaN/infinite durations. | [Transcription](../app/transcription.py) validates payload shapes and timestamp conversions; [audio probing](../app/footage.py) rejects non-finite duration before paid transcription. Tests cover malformed payloads and invalid timestamps/durations. |
| Medium | Transcription audio preparation ran before its cleanup `try/finally`, leaving partial FLAC uploads on failure/cancellation. FFmpeg progress parsing also swallowed `ValueError` raised by a callback as if it were invalid FFmpeg output. | Preparation now runs inside cleanup protection. [FFmpeg execution](../app/ffmpeg.py) separates parsing from callbacks and guarantees reader completion signaling. Tests cover preparation cancellation and callback failure. |
| Medium | API lifespan shutdown was after a bare `yield`; exceptions thrown through the lifespan context could bypass processor shutdown. UI code reached into worker-thread and state internals. | [API lifespan](../api.py) closes in `finally`; the dashboard uses `active`, and refresh error state belongs to the processor. An exceptional lifespan test verifies shutdown. |
| Low, maintenance | Dense one-line statements, inconsistent formatting, missing project-level lint/type configuration and no CI made changes difficult to review consistently. | Ruff formatting/linting, pinned development tools, type checks on eight core modules, a CI matrix and [extension documentation](ARCHITECTURE.md). Runtime dependency pins remain unchanged. |

Additional recovery regressions preserve existing guarantees: a complete output survives a checkpoint, upload or DONE-update failure; a known upload URL remains available to the FAILED update if its local checkpoint cannot be written; cleanup failure cannot reverse an acknowledged DONE; confirmed uploads are committed after cancellation. These guarantees are now owned and tested independently of the queue controller.

## Remaining limitations and decisions

| Priority / condition | Limitation | Recommended next step when needed |
| --- | --- | --- |
| High for multiple hosts | The file lock only coordinates processes sharing its lock directory. Baserow job acquisition is not a compare-and-set operation. Two independent hosts can process the same row. | Before supporting distributed workers, introduce atomic claims/leases in a transactional repository. Do not advertise the current lock as distributed. |
| High for automatic retry | Cloudinary upload and Baserow completion cannot be committed atomically. Timeouts can occur after a remote write succeeds; retries with a new output/public ID may create duplicates. | Add a durable job-attempt record, stable idempotency identifiers and a reconciliation operation before adding automatic failed-job retries. Current manual recovery remains necessary. |
| Medium; untrusted table writers | Downloader accepts arbitrary HTTP(S) destinations and follows redirects, including destinations on networks reachable from the worker. That is suitable only for trusted job authors and network placement. | A hosted/multi-tenant version needs an explicit egress policy that also validates redirects and DNS resolution. No blanket private-address block was added because local/self-hosted sources are supported. |
| Medium; public automation | `GET /run` mutates state. It is authenticated and non-cacheable, but GET semantics still make automation/prefetching error-prone. | Migrate clients to a POST trigger in a versioned API change, retaining a documented transition period for existing GET clients. |
| Medium; long-running workloads | Buffers and failed-job diagnostics are intentionally retained. There is no disk quota, retention policy or total wall-clock job deadline. HTTP timeouts are not a whole-batch deadline. | Add storage accounting and a retention policy that protects active attempts; add deadlines as a separate execution policy. |
| Medium; API evolution | Configuration remains nested dictionaries; existing provider modules and UI are not fully statically typed. Strict validation deliberately rejects unknown configuration keys. | Introduce typed settings per adapter incrementally, preserving the YAML contract. Extend the current mypy target list as modules are typed. |
| Low | Retry loops repeat across adapters, but their retry units differ: whole download, transcription request, idempotent row update and individual upload chunk. They do not honor `Retry-After` or add jitter. | Share a narrowly scoped retry/backoff policy when needed; preserve each adapter's transaction and stream boundaries. |
| Low | Caption segmentation remains punctuation-based, including abbreviations; overlapping provider sentences are rejected. A custom planner must still satisfy the default renderer's validation. | Introduce a different segmentation/planning policy with representative transcript fixtures before changing timeline semantics. |

Checkpoint replacement is atomic at the filesystem-name level, not fsync-backed power-loss durability. Recovery can still require remote inspection if the machine crashes at an unfortunate point. A stronger durability requirement belongs with the durable-attempt/reconciliation work above.

## Verification scope

The original 67 tests passed after the initial refactor. Final local verification: **117 tests passed**, Ruff lint and formatting passed for all 41 Python files, mypy passed for eight core modules, and `git diff --check` passed. The expanded suite adds failure injection, concurrency, malformed input, boundary enforcement and artifact preservation checks.

Local validation uses Python 3.14.8 and the pinned runtime dependencies, with real FFmpeg, local HTTP downloads, API/TUI tests and mocked online services. Lint, formatting and mypy are also run. CI is configured for Python 3.13 and 3.14 but has not been executed on GitHub in this task. Windows locking and live Baserow/transcription/Cloudinary transactions have not been verified here. A Starlette warning about the HTTPX test-client integration remains visible; it does not fail the suite.
